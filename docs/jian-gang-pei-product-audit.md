# 简岗配 AI 产品审计摘要

更新时间：2026-07-16（8.6C-A）
审计性质：历史问题清单的当前摘要；以工作树和已提交版本为准，不代表线上已发布版本。

## 当前产品边界

- 未登录用户仅可使用本地 Mock 分析、本地简历导入、本地 JD 输入和本地历史记录。
- 页面必须说明：本模式仅用于体验产品流程，结果由本地规则生成，不调用真实大模型。
- 登录后才可看到平台 AI 与自带 API Key 的后续使用入口；当前两者都不执行真实模型调用。
- 平台 AI 的目标规则为每日最多 5 次、每月最多 30 次，且仅成功分析计次；当前仍处于测试阶段，`ENABLE_PLATFORM_AI = false`。
- 自带 API Key 的目标是仅保存在当前浏览器、可清除且不上传 Supabase；真实调用尚未接入。
- 实际登录代码仍为 Supabase Magic Link；目标中的邮箱 6 位 OTP（登录注册合并）尚未实现。

## 已保留的安全基线

- Worker 保留 JWT 校验、输入校验、限流、请求幂等、原子预留、成功确认与失败恢复能力。
- 平台密钥和 Supabase 服务端密钥仅应存在于 Worker Secret；前端不得保存或暴露这些密钥。
- 文件导入在浏览器本地解析；Mock 分析不请求 Worker 或模型服务。
- 旧额度字段（包括 `platform_paid_credits`）暂时保留在数据库兼容层，但前端不读取、不展示、不依赖，标记为 deprecated。

## 仍待完成的真实能力

1. 邮箱 6 位 OTP 登录与注册合并流程。
2. 不破坏现有数据的每日/月度额度记录与服务端计数。
3. 平台 AI 的受控启用、真实服务端端到端验收和发布一致性核验。
4. 自带 API Key 的本地调用实现，以及保存、清除和失败状态的验收。
5. 登录用户在同一浏览器中的本地简历、JD 与历史记录隔离。

## 历史审计结论

此前的商业化、计次展示和线上发布问题不再作为当前页面规则。后续开发应先完成上述真实能力，并在有明确授权后再执行数据库变更、部署或真实服务验证。
